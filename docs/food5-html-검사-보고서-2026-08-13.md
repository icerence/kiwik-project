모바일과 데스크톱 모두 96점이다.

| 항목 | 내용 | 어떻게 고치는가 |
| --- | --- | --- |
| `color-contrast` | 일부 전경색과 배경색의 대비가 충분하지 않음 | 실패 요소를 개발자 도구로 확인하고 글자색 또는 배경색의 명도 차이를 WCAG 기준에 맞게 높인다 |

현재 스킬이 보존한 Lighthouse 요약에는 실패 요소의 선택자가 포함되지 않아 정확한 위치는 확인되지 않았다.

자동 검사로는 아래 항목을 확인할 수 없다.

1. 키보드 `Tab`만으로 화면 전체를 사용할 수 있는가
2. 포커스가 특정 영역에 갇히지 않는가
3. 시각적 순서와 DOM 순서가 일치하는가

| 항목 | 내용 | 어떻게 고치는가 |

| `image-aspect-ratio` | 표시된 이미지 비율이 원본 이미지 비율과 맞지 않음 | CSS로 한쪽 크기만 강제하지 말고 `width`·`height`, `aspect-ratio`, `object-fit`을 함께 조정한다 |

성능 측면에서는 이미지 크기 명시, 캐시 수명 개선, 렌더링 차단 요청 축소와 사용하지 않는 JavaScript 지연 로딩도 권고됐다.

## 7 - 먼저 할 일

1. 히어로와 본문 이미지를 WebP/AVIF로 최적화하고 LCP 이미지를 HTML에서 즉시 발견하도록 `preload` 또는 `fetchpriority="high"`를 검토한다. 모바일 LCP 21.9초와 약 4,022KiB의 전송량 개선에 가장 직접적이다.
2. `inline_1.js`의 모바일 메뉴 관련 변수 4개를 DOM에서 명시적으로 가져오고 실제 메뉴 숨김 클래스와 일치하는지 확인한다. 앵커 클릭 시 발생할 수 있는 `ReferenceError`를 막는다.
3. 이미지의 명시적 크기와 종횡비를 바로잡고 색상 대비 실패 요소를 확인한다. 데스크톱 CLS 0.118, 권장 사항과 접근성 감점을 함께 줄일 수 있다.

## 검사 도구와 한계

이 보고서는 W3C Nu HTML Checker, W3C CSS Validator, ESLint, Lighthouse 결과를 한국어로 옮긴 것이다. 문법 검사는 코드 규칙만 판단하므로 문법이 맞아도 화면이 의도와 다를 수 있다. 외부 CDN 압축 코드의 오류는 직접 수정 대상에서 제외했다. Lighthouse 점수는 네트워크와 측정 환경에 따라 달라질 수 있으며 접근성 점수는 자동 판정 가능한 항목만 반영한다.
