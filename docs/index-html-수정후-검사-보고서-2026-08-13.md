이번 수정으로 확인 가능한 가장 뚜렷한 변화는 이미지 전송량과 접근성이다. 화면 구성과 이미지 내용은 유지하면서, 모바일에서 불필요하게 큰 원본 이미지를 받지 않도록 바꿨다.

## 1. 무엇을 어떻게 변경했는가

### Instagram 이미지 최적화

기존 930px 너비 PNG 4장을 같은 3:4 비율의 480×640 WebP로 변환했다.

| 구분 | 4장 합계 |
| --- | ---: |
| 기존 PNG | 5,975,079바이트 |
| 새 WebP | 181,388바이트 |
| 감소율 | 약 97.0% |

`index.html`은 새 WebP를 참조하고 `width`, `height`, `loading="lazy"`, `decoding="async"`를 사용한다. 원본 PNG는 삭제하지 않았으며 현재 메인 페이지에서는 불러오지 않는다.

### Hero LCP 이미지 우선순위 조정

- `hero-960.webp`를 추가했다.
- `srcset`과 `sizes="100vw"`로 화면 폭에 맞는 파일을 선택하도록 했다.
- `fetchpriority="high"`를 지정했다.
- `width="1920"`, `height="1080"`을 명시해 이미지 로드 전에도 비율을 계산할 수 있게 했다.

Lighthouse가 지적한 LCP 요소는 수정 후에도 의도대로 Hero 배경 이미지다. 초기 HTML에서 바로 발견되고 높은 요청 우선순위를 갖는다.

### 뉴스와 배너 반응형 이미지

- `news-featured-480.webp`, `news-featured-960.webp` 추가
- `global-citizen-banner-640.webp`, `global-citizen-banner-1280.webp` 추가
- 각 이미지에 `srcset`, `sizes`, 고유 크기, 지연 로딩과 비동기 디코딩 적용

모바일이 데스크톱 크기의 이미지를 그대로 받는 문제를 줄였다.

### 색상 대비 개선

접근성용 강조 토큰 `--color-lime-700: #477a08`을 추가했다. 흰색과 약 5.18:1 대비를 내므로 일반 텍스트 기준 4.5:1을 충족한다.

적용 대상은 다음과 같다.

- 포트폴리오 안내 라벨
- Eco-Caring 카드 배지와 제목
- 추진방향 아이콘의 보조 문구
- 모바일의 짙은 녹색 배경 위 섹션 라벨은 `green-50`으로 변경

수정 후 Lighthouse의 `color-contrast` 검사는 모바일과 데스크톱 모두 통과했고 접근성 점수는 96점에서 100점으로 올랐다.

### CSS와 JavaScript 정리

- W3C가 해석하지 못했던 `calc(100% + var(...) + var(...))` 너비 식을 제거했다.
- 같은 시각적 여유를 `margin-inline-end`와 전용 토큰으로 표현했다.
- `document.write()` 안의 `<\/script>` 정규식 이스케이프 형태를 제거했다.
- 데스크톱 스크립트는 `document.createElement('script')`로 생성해 추가한다.

## 2. 문법 및 린트 재검사

### HTML

수정 후 오류 5건, 경고 1건이다.

- 오류 5건은 `type="text/tailwindcss"`, `@theme`, `@utility`에 대한 W3C 지적이다.
- 이 항목들은 Tailwind Browser CDN 전용 문법이며 이번 수정 범위의 실제 HTML 구조 오류는 아니다.
- 경고 1건은 Hero의 대표 `h1`에 대한 일반적인 제목 구조 권고다. 페이지 대표 제목으로 사용되고 있다.

### CSS

W3C CSS Validator가 두 번 연속 HTTP 520을 반환해 전체 CSS 결과는 확인하지 못했다. 다만 이전에 프로젝트 코드에서 지적된 `width: calc(100% + var(...) + var(...))` 선언은 제거했고, Chrome 모바일·데스크톱 렌더링에서 대체 규칙이 적용되는 것을 확인했다.

### JavaScript

수정된 로컬 JavaScript 직접 검사 결과는 오류 3건, 경고 0건이다.

| 파일 | 내용 | 판단 |
| --- | --- | --- |
| `common/components.js` | `DOMParser`, `CustomEvent` 미정의 | 브라우저 전역 변수를 Node 기준으로 검사한 오탐 |
| `assets/js/main.js` | `getComputedStyle` 미정의 | 브라우저 전역 변수를 Node 기준으로 검사한 오탐 |

이전 인라인 스크립트의 `no-useless-escape` 항목은 해당 표현 자체를 없애 해소했다.

## 3. Lighthouse 재검사

### 로컬 결과

| 지표 | 모바일 | 데스크톱 |
| --- | ---: | ---: |
| 성능 | 53점(3회 중앙값) | 77점 |
| 접근성 | 100점 | 100점 |
| 권장 사항 | 100점 | 100점 |
| SEO | 100점 | 100점 |
| FCP | 9.9초 | 1.8초 |
| LCP | 11.4초 | 2.1초 |
| TBT | 0ms | 0ms |
| CLS | 0.102(3회 중앙값) | 0.116 |

모바일 3회 성능 점수는 55점, 53점, 53점이었다.

이 성능 점수는 수정 전 공개 URL의 72점·95점과 직접 비교하면 안 된다. 로컬 검사에서는 Tailwind Browser CDN 요청이 약 8.76초의 렌더링 차단으로 측정됐지만, 수정 전 공개 URL에서는 약 1.07초였다. 검사 대상 호스트와 CDN 응답 상태가 다르기 때문이다. 따라서 성능 점수의 최종 전후 비교는 배포 후 공개 URL을 같은 조건으로 다시 측정해야 한다.

반면 다음 결과는 수정 효과를 직접 확인할 수 있다.

- 네트워크 전송량: 약 4,855KiB → 약 2,056KiB
- 모바일 이미지 예상 절감량: 약 3,007KiB → 약 149KiB
- 접근성: 96점 → 100점
- 색상 대비 실패 요소: 13개 → 0개

## 4. 시각 및 동작 확인

- 1440×1000 데스크톱과 390×844 모바일에서 Chrome 렌더링을 확인했다.
- Hero 이미지의 비율과 중심 배치는 유지됐다.
- 포트폴리오 안내 모달과 공통 헤더가 표시됐다.
- Eco-Caring 카드의 구조는 유지됐고 강조색만 접근성 기준을 만족하는 진한 녹색으로 변경됐다.
- 새 이미지 파일은 원본과 같은 화면 비율을 사용하므로 레이아웃 크기 변화는 없다.

## 5. 남은 항목

1. 배포 후 공개 URL에서 모바일·데스크톱 Lighthouse를 다시 실행해 실제 성능 점수를 확정해야 한다.
2. Tailwind Browser CDN은 여전히 가장 큰 렌더링 차단 요인이다. 이를 제거하려면 사전 빌드 CSS 방식으로 프로젝트 구조를 변경해야 하므로 별도 작업으로 다루는 것이 적절하다.
3. GitHub Pages의 짧은 캐시 수명은 HTML 코드에서 직접 제어하기 어렵다. 파일 크기 감소로 우선 대응한 상태다.

## 검사 도구의 한계

W3C와 ESLint는 Tailwind 전용 문법, 외부 라이브러리, 브라우저 전역 변수를 오탐할 수 있다. 로컬 Lighthouse는 공개 GitHub Pages와 네트워크 경로가 달라 성능 점수를 그대로 비교할 수 없다. 접근성 자동 검사는 키보드 이동 순서와 실제 보조기기 사용성 전체를 보장하지 않는다.
