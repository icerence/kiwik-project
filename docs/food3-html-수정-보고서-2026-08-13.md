## 1 - 고친 것

### 1) 헤더 하위 메뉴의 ARIA 오류

`aria-label`이 붙은 일반 `div`에 의미 역할이 없어 W3C 오류가 발생했다. `role="group"`을 추가해 하위 메뉴 묶음이라는 의미를 명시했다.

```diff
- <div class="site-header-dropdown__inner" aria-label="전체 하위 메뉴">
+ <div class="site-header-dropdown__inner" role="group" aria-label="전체 하위 메뉴">
```

재검사에서 해당 오류가 사라져 HTML 오류가 3건에서 2건으로 줄었다.

### 2) 모바일 메뉴의 미선언 변수와 클래스명 오류

앵커 링크 클릭 처리에서 `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose`를 선언하지 않고 사용하고 있었다. 또한 공통 컴포넌트가 실제로 사용하는 `is-hidden` 대신 `hidden`을 조작하고 있었다.

네 요소를 `document.getElementById`로 가져오고, 네 요소가 모두 존재할 때만 메뉴 상태를 변경하도록 방어 조건을 추가했다. 메뉴와 아이콘에는 실제 공통 클래스인 `is-hidden`을 적용했다.

```diff
+ const mobileMenu = document.getElementById('mobile-menu');
+ const menuBtn = document.getElementById('menu-btn');
+ const menuIconOpen = document.getElementById('menu-icon-open');
+ const menuIconClose = document.getElementById('menu-icon-close');

- if (!mobileMenu.classList.contains('hidden')) {
+ if (mobileMenu && menuBtn && menuIconOpen && menuIconClose &&
+     !mobileMenu.classList.contains('is-hidden')) {
    menuBtn.setAttribute('aria-expanded', 'false');
-   mobileMenu.classList.add('hidden');
-   menuIconOpen.classList.remove('hidden');
-   menuIconClose.classList.add('hidden');
+   mobileMenu.classList.add('is-hidden');
+   menuIconOpen.classList.remove('is-hidden');
+   menuIconClose.classList.add('is-hidden');
  }
```

모바일 390×844 브라우저에서 메뉴를 연 뒤 `#site-footer` 앵커를 선택해 확인했다. 메뉴에는 `is-hidden`이 다시 적용됐고 버튼의 `aria-expanded`는 `false`로 돌아왔으며 페이지 런타임 오류는 발생하지 않았다.

### 3) PNG 이미지 3장을 WebP로 전환

검사 보고서가 LCP와 전체 전송량의 가장 큰 원인으로 지목한 콘텐츠 이미지 3장을 원본 해상도 1536×672로 유지하면서 WebP 품질 82로 인코딩했다.

| 이미지 | PNG | WebP | 감소율 |
| --- | ---: | ---: | ---: |
| `food3-hero` | 1,870,882바이트 | 161,782바이트 | 약 91.4% |
| `food3-philosophy-forest` | 1,969,039바이트 | 223,272바이트 | 약 88.7% |
| `food3-traceability` | 1,353,494바이트 | 65,976바이트 | 약 95.1% |
| **합계** | **5,193,415바이트** | **451,030바이트** | **약 91.3%** |

`food3.html`의 세 이미지 경로를 새 WebP 파일로 변경했다. 기존 PNG는 현재 코드에서 사용하지 않지만, 파일 삭제 승인을 받지 않아 저장소에 그대로 두었다.

### 4) 이미지 로딩 우선순위와 크기 지정

히어로 이미지에는 `fetchpriority="high"`를 추가해 브라우저가 LCP 후보를 먼저 내려받도록 했다. 화면 아래에 있는 숲 이미지와 식품이력제 이미지에는 `loading="lazy"`를 적용했다.

세 이미지 모두 원본 비율에 맞는 `width="1536" height="672"`를 명시했다. 브라우저가 이미지 다운로드 전에 비율을 계산할 수 있어 이미지 영역의 레이아웃 이동을 줄이는 데 도움이 된다.

## 2 - 수정하지 않은 항목과 이유

| 항목 | 이유 |
| --- | --- |
| HTML 오류 2건(`<style type="text/tailwindcss">`, `@theme`) | Tailwind v4 브라우저 빌드가 사용하는 문법으로, 제거하면 페이지 디자인 토큰이 동작하지 않는다. W3C 검사기의 인식 한계다 |
| HTML 경고 39건 | HTML5 빈 요소의 끝 슬래시에 관한 권고이며 페이지 동작에 영향을 주지 않는다 |
| Swiper CSS 오류·외부 CDN JavaScript 린트 오류 | 프로젝트가 직접 작성한 코드가 아니므로 수정 대상에서 제외했다 |
| CDN 전역 변수 `gsap`, `ScrollTrigger`, `ScrollSmoother`, `ScrollToPlugin` | 페이지에서 CDN으로 불러오는 실제 전역이며 파일 단위 ESLint 검사의 오탐이다 |
| 색 대비 문제 | 기존 검사 결과에 실패 요소의 선택자가 없어 이번 수정 범위에서 정확한 대상을 확정할 수 없었다 |
| 캐시 정책과 렌더링 차단 리소스 | GitHub Pages 응답 정책과 외부 CDN 로딩 구조에 관련된 별도 작업이다 |
| 기존 PNG 3장 삭제 | 코드에서 더 이상 참조하지 않지만 파일 삭제는 사용자 승인이 필요해 보존했다 |

## 4 - 배포 후 다시 확인할 것

이번 변경은 아직 로컬 코드에만 있으므로 공개 주소의 Lighthouse 점수에는 반영되지 않았다. 커밋·푸시 후 GitHub Pages 배포가 완료되면 `https://icerence.github.io/kiwik-project/food3.html`을 모바일과 데스크톱으로 다시 검사해야 한다.

비교 기준은 기존 검사 결과인 성능 모바일 68점·데스크톱 73점, 모바일 LCP 27.0초·데스크톱 LCP 4.1초다. 이미지 전송량은 크게 줄었지만 실제 점수와 LCP 개선 폭은 배포 후 측정값으로만 확정할 수 있다.

## 검사 도구와 한계

W3C Nu HTML Checker로 로컬 HTML을 재검사했고 Chromium 기반 브라우저 자동화로 모바일·데스크톱 이미지 로딩, 메뉴 상태, 가로 넘침과 런타임 오류를 확인했다. Lighthouse 점수는 네트워크·서버 상태에 따라 달라지고 로컬 변경은 공개 URL에 반영되지 않으므로 이번 보고서에서는 새 점수를 추정하지 않았다.
