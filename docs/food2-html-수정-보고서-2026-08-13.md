`food.html`에서 쓴 방식(`docs/food-html-수정-보고서-2026-08-13.md` 참고)을 그대로 적용했다. `common/components.js`는 그 작업에서 이미 사이트 전체 공통으로 고쳐졌으므로(`var` 74건 → `let`/`const`) food2.html에도 자동으로 적용돼 있어 이번에는 손댈 게 없었다.

## 1 - 고친 것

### 1) `food2.html` 195번째 줄 — `div[aria-label]` HTML 오류

`food.html`과 동일한 문제였다. `role` 속성이 없는 `div`에 `aria-label`만 있어 W3C 검사기가 오류로 표시했다.

```diff
- <div class="site-header-dropdown__inner" aria-label="전체 하위 메뉴">
+ <div class="site-header-dropdown__inner" role="group" aria-label="전체 하위 메뉴">
```

### 2) `food2.html` 인라인 스크립트 — 미선언 변수로 인한 실제 버그

`food.html`과 완전히 같은 코드가 그대로 복사돼 있었다. `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose`를 선언하지 않고 써서 앵커 클릭 시 `ReferenceError`가 났고, 존재하지 않는 `hidden` 클래스를 토글하고 있었다.

```diff
+ const mobileMenu = document.getElementById('mobile-menu');
+ const menuBtn = document.getElementById('menu-btn');
+ const menuIconOpen = document.getElementById('menu-icon-open');
+ const menuIconClose = document.getElementById('menu-icon-close');
+
  document.querySelectorAll('a[href^="#"]').forEach((a) => {
    a.addEventListener('click', (e) => {
      const href = a.getAttribute('href');
      if (href && href.length > 1 && document.querySelector(href)) {
        e.preventDefault();
        smoother.scrollTo(href, true, 'top top');
-       if (!mobileMenu.classList.contains('hidden')) {
-         menuBtn.setAttribute('aria-expanded', 'false');
-         mobileMenu.classList.add('hidden');
-         menuIconOpen.classList.remove('hidden');
-         menuIconClose.classList.add('hidden');
+       if (mobileMenu && !mobileMenu.classList.contains('is-hidden')) {
+         menuBtn.setAttribute('aria-expanded', 'false');
+         mobileMenu.classList.add('is-hidden');
+         menuIconOpen.classList.remove('is-hidden');
+         menuIconClose.classList.add('is-hidden');
        }
      }
    });
  });
```

### 3) 히어로 이미지 압축·WebP 전환 — 성능 개선

검사 보고서가 성능 점수(모바일 63점)를 가장 크게 깎는 원인으로 지목한 항목이다. `food2-hero.png`(1774×887, 2,391KB)를 같은 해상도로 유지한 채 WebP로 재인코딩했다.

| 파일 | 크기 | 용량 |
| --- | --- | --- |
| food2-hero.webp | 1774×887 (해상도 그대로, 재인코딩만) | 2,391KB → 212KB (91%↓) |

`food2.html`을 직접 훑어 다른 본문 이미지가 있는지 확인했는데, 로고·푸터·SNS 아이콘은 이미 수 KB 수준으로 작아서 손댈 필요가 없었고(`sns-tistory.png`, `sns-youtube.png`는 확장자만 `.png`이고 실제로는 370바이트대 GIF라 무시할 수준이다), 히어로 이미지가 사실상 유일한 대용량 자산이었다. `fetchpriority="high"`는 이미 걸려 있어 그대로 뒀다. 더는 쓰지 않는 원본 `food2-hero.png`는 저장소에서 지웠다(`git rm`).

이미지 변환은 `food.html` 작업 때 스크래치 폴더에 설치해 둔 `sharp`를 그대로 재사용했다. 변환 후 이미지를 직접 열어 원본과 같은 그림인지 확인했다.

## 2 - 수정하지 않은 항목과 이유

| 항목 | 이유 |
| --- | --- |
| HTML 오류 3건 (`<style type="text/tailwindcss">`, `@theme`, `@utility`) | Tailwind v4 CDN 문법이라 지우면 디자인 토큰이 깨진다. 검사기가 Tailwind 문법을 모를 뿐인 오탐 |
| HTML 경고 32건 (void 요소 trailing slash) | 동작에 영향 없음. 검사 보고서에서도 "필수 수정 아님"으로 분류 |
| CSS 오류 30건·경고 36건 | 전부 swiper CDN 외부 파일에서 나옴. 직접 작성 코드는 오류 0건 |
| JS `no-var` 74건 → `let`/`const` | `food.html` 작업에서 `common/components.js`를 이미 고쳐서 이번에는 할 게 없었다 |
| JS `no-undef` — `DOMParser`/`CustomEvent`/CDN 전역(`gsap` 등) | 실제 오류가 아닌, 린트 설정·파일 단위 검사의 한계 |
| 성능 — 캐시 정책, 렌더링 차단 스크립트 | `food.html` 보고서와 같은 이유로 이번 범위에서 뺐다: 캐시는 서버 헤더 영역이라 코드로 못 바꾸고, 렌더링 차단 스크립트 구조 변경은 애니메이션에 영향을 줄 수 있어 별도 승인이 필요하다 |

## 3 - 재검사 결과

로컬 파일 기준 W3C Nu HTML Checker로 다시 확인했다(ESLint는 인라인 스크립트를 로컬 파일에서 자동 추출하지 못해 생략, 코드는 육안으로 대조).

| 검사 | 수정 전 | 수정 후 |
| --- | --- | --- |
| HTML 오류 | 4건 | 3건(전부 Tailwind v4 문법 오탐, 실질적 문제 없음) |

이번 수정은 모두 로컬에만 있고 커밋·배포 전이다. `https://icerence.github.io/kiwik-project/food2.html`은 아직 수정 전 버전이므로, 배포 후 같은 URL로 Lighthouse를 다시 돌려야 성능 점수 변화(현재 모바일 63점 / 데스크톱 73점 대비)를 확인할 수 있다.

## 검사 도구와 한계

W3C Nu HTML Checker로 문법을 다시 확인했고, 인라인 스크립트 수정은 `food.html`에서 이미 검증한 것과 동일한 패턴이라 코드를 직접 대조하는 방식으로 확인했다. 이번 세션에는 브라우저 자동화 도구가 없어 실제 브라우저 렌더링·모바일 메뉴 동작 확인은 하지 못했다. 배포 전 브라우저로 직접 열어보는 것을 권한다.
