### 공통으로 발견된 문제

1. 대용량 PNG와 느린 LCP
   - 페이지별 핵심 이미지가 수 MB 단위 PNG로 제공돼 모바일 LCP가 16.5~36.9초까지 늘어났다.
   - 히어로 이미지 우선순위, 본문 이미지 지연 로딩, 이미지 고유 크기 정보도 일부 페이지에서 빠져 있었다.

2. 헤더 하위 메뉴의 ARIA 문법 오류
   - 역할이 없는 `div`에 `aria-label="전체 하위 메뉴"`를 사용했다.
   - `role="group"`을 추가하는 방식으로 수정했다.

3. 모바일 메뉴 앵커 처리 오류
   - `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose`를 선언하지 않고 사용했다.
   - 공통 컴포넌트가 쓰는 `is-hidden` 대신 존재하지 않는 `hidden` 클래스를 조작했다.
   - 앵커 클릭 시 `ReferenceError`가 발생하고 메뉴 닫기 처리가 중단될 수 있었다.

4. 외부 라이브러리 검사 오류
   - W3C CSS 오류 30건은 모두 외부 Swiper CDN CSS에서 발생했다.
   - ESLint 오류 대부분은 Tailwind 브라우저 런타임, GSAP, ScrollTrigger, ScrollSmoother, ScrollToPlugin, Swiper 압축 파일에서 발생했다.
   - 직접 작성한 코드가 아니므로 수정 대상에서 제외했다.

5. 검사기 오탐
   - `<style type="text/tailwindcss">`, `@theme`, 페이지에 따라 `@utility`를 W3C 검사기가 표준 오류로 표시했다.
   - Tailwind v4 브라우저 빌드에 필요한 문법이므로 제거하지 않았다.
   - `DOMParser`, `CustomEvent`, `gsap` 계열 전역은 ESLint 환경 설정에 따른 `no-undef` 오탐으로 분류했다.

## 3. 적용한 수정

### 전체 페이지 공통

- 헤더 하위 메뉴에 `role="group"` 추가
- 모바일 메뉴 DOM 요소를 `document.getElementById`로 명시적으로 조회
- 네 요소가 모두 있을 때만 상태를 변경하도록 방어 조건 추가
- 숨김 상태 클래스명을 `is-hidden`으로 통일

## 5. 결과 판정

- 데스크톱 성능은 다섯 페이지 모두 상승했다. 특히 `food.html`은 72점에서 95점으로 올라 좋음 구간에 진입했다.
- 모바일 LCP는 전 페이지에서 7.4~26.3초 단축돼 이미지 최적화 효과가 확인됐다.
- `food3.html` 모바일은 LCP가 27.0초에서 9.9초로 개선됐지만 성능 종합 점수는 68점에서 56점으로 하락했다. 단일 실행 변동과 렌더 차단·초기 표시 지연의 영향을 분리하려면 3회 반복 측정이 필요하다.
- 접근성은 전 페이지 96점이다. 공통 감점 항목은 일부 텍스트의 낮은 색 대비다.
- SEO는 전 페이지 모바일·데스크톱 모두 100점이다.
- 모바일 성능은 전 페이지가 개선 필요 구간이다. 현재 공통 병목은 렌더 차단 요청, 느린 초기 콘텐츠 표시, 외부 CDN 자원과 캐시 정책이다.

## 6. 남은 작업

1. 모바일 성능을 판단할 페이지는 Lighthouse를 3회 반복해 중앙값으로 비교한다. 특히 `food3.html`의 점수 하락이 지속되는지 확인한다.
2. 브라우저 개발자 도구에서 색 대비 실패 요소를 특정하고 WCAG 2.1 AA 기준에 맞춘다.
3. Tailwind 브라우저 빌드와 애니메이션 CDN의 렌더 차단을 줄일 수 있는지 별도 검토한다. 구조를 바꾸면 화면과 애니메이션에 영향을 줄 수 있으므로 별도 작업으로 진행한다.

코드에서 더 이상 참조하지 않는 기존 PNG는 `food3` 3장, `food4` 12장, `food5` 2장이 아직 `assets/images`에 남아 있다. 이 파일들은 현재 페이지 전송량에는 포함되지 않지만 저장소 용량을 차지한다.

## 검사 도구와 한계

이 보고서는 W3C Nu HTML Checker, W3C CSS Validator, ESLint와 Lighthouse 결과를 통합한 것이다. 문법 검사는 코드 규칙만 판단하므로 화면이 의도대로 보이는지 보장하지 않는다. 외부 CDN 압축 코드에서 발생한 오류는 프로젝트 코드의 오류와 분리해야 한다. Lighthouse 점수는 네트워크와 측정 시점에 따라 변하며 이번 배포 후 값은 각 환경 1회 측정 결과다. 접근성 96점은 자동 검사 항목만 반영하므로 키보드 이동, 포커스 순서와 실제 사용성은 별도 수동 확인이 필요하다.
