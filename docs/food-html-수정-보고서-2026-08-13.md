## 1 - 고친 것

### 1) `food.html` 228번째 줄 — `div[aria-label]` HTML 오류

**문제**: `role` 속성이 없는 `div`에 `aria-label`을 넣어 W3C 검사기가 오류로 표시했다.

**수정**:
```diff
- <div class="site-header-dropdown__inner" aria-label="전체 하위 메뉴">
+ <div class="site-header-dropdown__inner" role="group" aria-label="전체 하위 메뉴">
```

`role="group"`을 추가해 스크린리더가 이 영역을 하나의 묶음으로 인식하게 했다. 재검사 결과 이 오류는 사라졌다.

### 2) `food.html` 인라인 스크립트 — 미선언 변수로 인한 실제 버그

**문제**: 문서 맨 아래 `<script>`가 앵커(`#`) 링크를 클릭했을 때 모바일 메뉴를 닫는 코드에서 `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose` 네 변수를 어디에서도 선언하지 않고 사용했다. 실제 DOM에는 `id="mobile-menu"`, `id="menu-btn"`, `id="menu-icon-open"`, `id="menu-icon-close"`로 존재하는데 이 스크립트가 그 값을 가져오지 않았다. 앵커를 클릭하면 `ReferenceError: mobileMenu is not defined`가 나면서 이 코드 블록이 멈췄다. 더해서, 실제 메뉴를 숨길 때 쓰는 클래스명은 `is-hidden`인데 코드는 존재하지 않는 `hidden` 클래스를 토글하고 있어, 설령 변수가 선언돼 있었어도 메뉴가 제대로 닫히지 않았을 것이다.

**수정**:
```diff
+ const mobileMenu = document.getElementById('mobile-menu');
+ const menuBtn = document.getElementById('menu-btn');
+ const menuIconOpen = document.getElementById('menu-icon-open');
+ const menuIconClose = document.getElementById('menu-icon-close');
+
  document.querySelectorAll('a[href^="#"]').forEach((a) => {
    a.addEventListener('click', (e) => {
      const href = a.getAttribute('href');
      if (href && href.length > 1 && document.querySelector(href)) {
        e.preventDefault();
        smoother.scrollTo(href, true, 'top top');
-       if (!mobileMenu.classList.contains('hidden')) {
-         menuBtn.setAttribute('aria-expanded', 'false');
-         mobileMenu.classList.add('hidden');
-         menuIconOpen.classList.remove('hidden');
-         menuIconClose.classList.add('hidden');
+       if (mobileMenu && !mobileMenu.classList.contains('is-hidden')) {
+         menuBtn.setAttribute('aria-expanded', 'false');
+         mobileMenu.classList.add('is-hidden');
+         menuIconOpen.classList.remove('is-hidden');
+         menuIconClose.classList.add('is-hidden');
        }
      }
    });
  });
```

네 요소를 `getElementById`로 가져오도록 선언을 추가하고, `common/components.js`가 실제로 쓰는 클래스명(`is-hidden`)에 맞췄다. 이제 모바일 메뉴가 열린 채로 앵커 링크를 클릭하면 메뉴가 정상적으로 닫힌다.

### 3) `common/components.js` — `var` 74건을 `let`/`const`로 교체

**문제**: 파일 전체에서 변수 선언에 옛 방식인 `var`를 74곳에서 썼다. `var`는 함수 스코프라 블록 스코프인 `let`/`const`보다 의도치 않은 값 덮어쓰기에 취약하다.

**수정**: 74곳을 아래 기준으로 나눠 바꿨다.

- 선언 뒤 값이 다시 대입되는 4곳 → `let`: `searchDocuments`(349번째 줄), `ready`(350번째 줄), `loading`(351번째 줄), `ticking`(458번째 줄)
- 나머지 70곳(선언 뒤 재대입 없음) → `const`

이 파일은 `food.html`뿐 아니라 사이트의 모든 페이지가 공통으로 불러 쓰는 헤더·푸터 스크립트라, 이번 수정은 `food.html`만이 아니라 사이트 전체에 적용된다. 동작을 바꾸지 않는 기계적 치환이라 기능상 영향은 없다.

이 파일에 남은 오류 2건(`DOMParser`, `CustomEvent`가 정의되지 않음)은 실제 버그가 아니다. 둘 다 브라우저 표준 API인데, 이번 검사에 쓴 ESLint 설정에 `env: browser`가 빠져 있어 나는 오탐이라 검사 보고서에서도 이미 그렇게 판단했다. 코드는 그대로 뒀다.

### 4) 이미지 압축·WebP 전환 — 성능 개선

**문제**: `food.html`이 쓰는 사진 7장이 실제 화면 표시 크기에 비해 지나치게 큰 원본 그대로였다. 특히 `size-10`(40px)로 표시되는 아이콘 3장이 1024×1024 원본 PNG(각 800KB~1.5MB)를 그대로 쓰고 있었다. 검사 보고서에서 성능 점수(모바일 51점)를 깎는 가장 큰 원인으로 지목한 항목이다.

**수정**: 각 이미지를 실제 표시 크기의 2배(레티나 대응)로 리사이즈하고 WebP로 다시 인코딩했다. 파일명이 정확히 무엇을 표시하는지 코드에서 바로 알 수 있게 확장자만 `.png` → `.webp`로 바꾸고, `food.html`의 여섯 군데 `<img src>`도 함께 고쳤다. 더는 쓰지 않는 원본 PNG 7장은 저장소에서 지웠다(`git rm`).

| 파일 | 원본 크기 | 조정 후 | 용량 |
| --- | --- | --- | --- |
| food-hero.webp | 1536×672 (그대로, 재인코딩만) | 1536×672 | 1,599KB → 134KB (92%↓) |
| food-video-1.webp | 1536×672 | 1100×481 (표시 영역의 2배) | 1,237KB → 33KB (97%↓) |
| food-video-2.webp | 1536×672 | 1100×481 | 1,455KB → 57KB (96%↓) |
| food-plate.webp | 1024×1024 | 640×640 (`size-80`의 2배) | 1,099KB → 34KB (97%↓) |
| food-guideline-exercise.webp | 1024×1024 | 96×96 (`size-10`의 2배) | 791KB → 1KB (100%↓) |
| food-guideline-diet.webp | 1024×1024 | 96×96 | 1,322KB → 2KB (100%↓) |
| food-guideline-sleep.webp | 1024×1024 | 96×96 | 1,460KB → 2KB (100%↓) |
| **합계** | | | **8,958KB → 263KB (약 97%↓)** |

부수적으로 두 가지를 더했다.

- 히어로 이미지(`food-hero.webp`)에 `fetchpriority="high"`를 추가했다. LCP(최대 콘텐츠 표시 시간) 요소로 지목된 이미지라, 브라우저가 이 이미지를 우선 내려받도록 힌트를 준다.
- 나머지 6장에는 `loading="lazy"`를 추가했다. 뷰포트에 바로 보이지 않는 이미지라 스크롤해서 도달하기 전까지 불러오지 않는다.

이미지 변환은 리사이즈·WebP 인코딩 도구(`sharp`)가 로컬에 없어 임시 스크래치 폴더에 한 번만 설치해 처리했으며, 프로젝트 저장소에는 어떤 의존성도 추가하지 않았다. 변환 후 각 이미지를 직접 열어 원본과 같은 그림인지, 해상도가 깨지지 않았는지 확인했다.

## 2 - 수정하지 않은 항목과 이유

| 항목 | 이유 |
| --- | --- |
| HTML 오류 2건 (`<style type="text/tailwindcss">`, `@theme`) | Tailwind v4 CDN(브라우저 빌드)이 요구하는 문법이다. 지우면 페이지의 커스텀 디자인 토큰이 전부 깨진다. W3C 검사기가 Tailwind 문법을 모를 뿐인 오탐이라 코드 수정 대상이 아니다 |
| HTML 경고 32건 (void 요소 trailing slash) | 동작에 영향이 없는 스타일 표기다. 검사 보고서에서도 "필수 수정은 아님"으로 분류했다. 대량 수정이 다른 부분에 영향을 줄 수 있어 이번 범위에서 뺐다 — 원하면 별도로 정리 가능 |
| 성능 — 캐시 정책(9,620 KiB 절감 가능) | 캐시 수명은 GitHub Pages 서버가 응답 헤더로 내려주는 값이라 HTML/JS 코드로는 바꿀 수 없다 |
| 성능 — 렌더링 차단 스크립트(Tailwind CDN·GSAP·Swiper) | `<head>`에서 동기 로드하는 구조 자체를 바꾸는 작업이라, 애니메이션·레이아웃 동작에 영향을 줄 수 있어 별도로 다루는 게 안전하다고 판단했다. 진행하려면 별도 승인이 필요하다 |
| JS `no-undef` — CDN 전역(`gsap`, `ScrollTrigger` 등) | 실제 오류가 아닌, 파일 단위로 검사하는 린트의 한계다 |
