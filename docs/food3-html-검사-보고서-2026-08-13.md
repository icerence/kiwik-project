가장 먼저 고칠 것: **최대 콘텐츠 표시 시간(LCP)** — 모바일 27.0초(!), 데스크톱 4.1초. `food.html`·`food2.html`보다 훨씬 나쁘다. 원인은 두 가지가 겹쳤다: ① `food3-hero.png`(1827KB), `food3-philosophy-forest.png`(1923KB), `food3-traceability.png`(1322KB) 세 장이 전부 1.3~1.9MB짜리 원본 PNG 그대로라 페이지 총 용량이 6.4MB에 달하고, ② 히어로 이미지(`food3-hero.png`)에 `food.html`·`food2.html`과 달리 `fetchpriority="high"`가 빠져 있어 브라우저가 이 이미지를 우선순위 낮게 나중에 발견한다(Lighthouse의 `lcp-discovery-insight` 항목). 이 두 가지만 손봐도 LCP가 크게 줄어든다.

> Lighthouse는 두 번 다 PageSpeed Insights API가 `HTTP 429`(무료 사용량 소진)로 실패해, 로컬 `lighthouse` CLI로 대체 측정했다. 환경에 따라 점수가 PSI 결과와 몇 점 차이 날 수 있다.

## 2 - CSS 문법 (W3C CSS Validator)

오류 30건은 전부 `https://cdn.jsdelivr.net/npm/swiper@12/swiper-bundle.min.css`(외부 CDN 라이브러리)에서 나왔다. 직접 작성한 코드가 아니므로 고칠 대상이 아니다.

경고 36건은 세부 위치가 제공되지 않았다. 오류가 전부 swiper CDN 파일에서 나온 것으로 볼 때 경고도 같은 출처일 가능성이 높다.

두 기준 모두 LCP가 점수를 가장 크게 깎는다. 페이지 총 전송량이 6,440 KiB로, `food.html`(3.7MB대)·`food2.html`(3.7MB대)보다도 크다. 이미지 최적화만으로 모바일 5,001 KiB / 데스크톱 3,570 KiB를 줄일 수 있다는 진단이다(`image-delivery-insight`). 실제로 페이지가 쓰는 이미지 3장(`food3-hero.png` 1,827KB, `food3-philosophy-forest.png` 1,923KB, `food3-traceability.png` 1,322KB) 합계가 약 5,072KB로 이 추정치와 거의 일치한다. 모바일에서만 `lcp-discovery-insight`(LCP 이미지를 HTML에서 즉시 찾을 수 있게 하고 지연 로딩을 피하라)가 추가로 걸렸는데, 히어로 이미지에 `fetchpriority="high"`가 빠져 있는 것이 원인으로 보인다. 그 외 캐시 수명이 짧은 리소스(`cache-insight`, 5.7MB대 절감 여지), 렌더링 차단 요청(`render-blocking-insight`, 최대 1.15초 절감 여지)도 함께 잡혔다.

1. 키보드 `Tab` 키만으로 화면 전체를 쓸 수 있는가
2. 포커스가 한 곳에 갇히지 않는가
3. 눈에 보이는 순서와 코드 순서가 맞는가

검색 최적화(SEO)는 모바일·데스크톱 모두 100점으로 통과했다.

권장 사항(Best Practices)은 모바일·데스크톱 모두 96점이다. 위 성능 표의 레이아웃 이동(`layout-shifts`, 데스크톱 3건)과 이미지 비율(`image-aspect-ratio`) 항목이 원인이다.

## 7 - 먼저 할 일

1. **이미지 3장 최적화**: `food3-hero.png`, `food3-philosophy-forest.png`, `food3-traceability.png`(합계 약 5MB)를 WebP로 바꾸고 실제 표시 크기에 맞게 리사이즈한다. `food.html`·`food2.html`에서 같은 작업으로 각각 91~97% 용량을 줄였다. LCP가 모바일 27초 → 수 초대로 크게 개선될 것으로 예상된다.
2. **히어로 이미지에 `fetchpriority="high"` 추가**: `food.html`·`food2.html`에는 이미 있는데 이 페이지에만 빠져 있다. 이미지 최적화와 별개로 LCP 우선순위 힌트를 준다.
3. **인라인 스크립트의 `mobileMenu` 등 미선언 변수 버그 수정 + line 200 `<div aria-label>`에 `role` 추가**: `food.html`·`food2.html`에서 이미 고친 것과 동일한 두 문제가 이 페이지에도 복사돼 있다.

## 검사 도구와 한계

이 보고서는 W3C Nu HTML Checker, W3C CSS Validator, ESLint(recommended), Lighthouse 결과를 옮긴 것입니다. 문법 검사는 코드가 규칙에 맞는지만 보므로, 문법이 맞아도 화면이 의도와 다르게 보일 수 있습니다. 린트는 파일 단위로 실행되어 다른 스크립트가 만드는 전역 변수를 오류로 잘못 표시할 수 있습니다. 성능 점수는 잴 때마다 몇 점씩 달라지며, 이번 측정은 PSI API 대신 로컬 CLI로 대체됐으므로 참고용으로만 봅니다. `common/components.js`의 `var` 74건은 이미 로컬에서 고쳐 커밋했으나 아직 배포되지 않아 이번 검사(배포본 기준)에는 반영되지 않았습니다. Lighthouse 접근성 점수는 자동으로 잡히는 항목만 반영하며, 색 대비·이미지 비율 문제는 어느 요소인지 사람이 직접 확인해야 합니다.
