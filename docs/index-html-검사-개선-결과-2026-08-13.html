02 · Changes

어떤 코드를 어떻게 바꿨는가

시각적 구성과 콘텐츠는 유지하면서 네트워크 전송, LCP 요청 우선순위, 색상 대비, 문법 호환성을 개선했습니다.

1

Instagram PNG를 WebP로 교체

930px 원본 PNG 4장을 화면 비율이 같은 480×640 WebP로 변환했습니다.

  • 4장 합계 5,975,079B → 181,388B
  • 이미지 자체 용량 약 97% 감소
  • loading="lazy", decoding="async" 적용
2

Hero LCP 요청을 앞당김

첫 화면의 가장 큰 콘텐츠인 Hero 이미지가 더 빠르게 발견되고 적절한 크기로 내려오도록 변경했습니다.

  • fetchpriority="high" 적용
  • 960w·1920w srcset 제공
  • width·height로 비율 사전 확보
3

배너·뉴스 이미지 반응형 처리

모바일 화면이 데스크톱 크기 이미지를 그대로 받지 않도록 480·640·960·1280px 후보를 추가했습니다.

  • srcset과 sizes 적용
  • 비가시 영역 이미지 지연 로딩
  • 이미지 예상 낭비 3,007KiB → 149KiB
4

WCAG 대비를 만족하는 강조색

연두색의 인상은 유지하면서 흰색과 4.5:1 이상 대비를 내는 #477a08 토큰을 추가했습니다.

  • 색상 대비 실패 요소 13개 → 0개
  • 카드 배지·제목·보조 문구에 적용
  • 접근성 점수 모바일·데스크톱 100점
5

CSS 계산식 오류 제거

W3C가 오류로 판정한 복합 calc() 너비를 제거하고 동일한 여유 공간을 음수 인라인 여백 토큰으로 표현했습니다.

  • 프로젝트 CSS 오류 1건 → 0건
  • 남은 CSS 오류 30건은 외부 Swiper 파일
  • 모바일·데스크톱 레이아웃 유지 확인
6

인라인 스크립트 린트 정리

document.write()와 불필요한 이스케이프를 제거하고 데스크톱 스크립트를 DOM API로 추가하도록 바꿨습니다.

  • 인라인 스크립트 오류 1건 → 0건
  • document.createElement('script') 사용
  • 모바일의 기본 연속 스크롤 동작 유지

04 · Performance

모바일 점수가 낮아진 이유

이미지 최적화와 별개로, Tailwind Browser CDN이 초기 렌더링 경로를 오래 막으면서 FCP와 LCP가 늦어졌습니다.

1회차54점
2회차55점
3회차54점
!

3회 중앙값 54점

FCP 중앙값은 9.2초, LCP 중앙값은 10.1초였습니다. 측정상 렌더링 차단 예상 절감 시간은 8.2~8.39초였고, 가장 큰 대상은 런타임에서 CSS를 생성하는 Tailwind Browser CDN입니다. 검사 전 측정의 렌더링 차단 예상치는 약 1.07초였으므로, 이번 모바일 점수 하락은 이미지보다 CDN 응답·런타임 처리의 영향을 크게 받은 결과로 해석됩니다.

05 · Standards

문법 검사에서 남은 항목

프로젝트가 직접 수정할 항목과 도구·외부 라이브러리에서 발생한 항목을 분리했습니다.

  • 도구 한계

    HTML 오류 5건·경고 1건

    오류 5건은 Tailwind v4의 text/tailwindcss, @theme, @utility를 W3C가 표준 CSS로 해석하지 못한 결과입니다. 경고 1건은 대표 Hero h1에 대한 일반 권고입니다.

  • 프로젝트 오류 0건

    CSS 오류 30건

    수정 전 프로젝트 CSS 오류 1건은 해소됐습니다. 배포 후 남은 30건은 모두 외부 swiper-bundle.min.css에서 발생했습니다.

  • 외부 코드 포함

    JS 오류 510건

    대부분 Tailwind·GSAP·Swiper 압축 코드입니다. 자체 코드의 2건은 DOMParser와 CustomEvent 브라우저 전역을 Node 기준으로 검사한 오탐이며, 인라인 오류는 0건입니다.

Next Step

다음 개선은 Tailwind 사전 빌드

이미지와 대비 문제는 해결됐습니다. 모바일 성능을 실제로 끌어올리려면 초기 렌더링 때 Tailwind Browser CDN이 CSS를 생성하는 구조를 바꾸는 것이 우선입니다.

  1. Tailwind v4를 빌드 단계에서 실행해 정적 CSS 파일을 생성합니다.
  2. 배포 HTML에서 Tailwind Browser CDN과 text/tailwindcss 블록을 제거합니다.
  3. 같은 조건으로 모바일 Lighthouse를 3회 측정해 중앙값을 다시 비교합니다.
  4. 데스크톱 CLS 0.116의 원인을 폰트 로딩과 초기 레이아웃 변화 중심으로 추가 점검합니다.
