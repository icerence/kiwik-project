## 1 - 고친 것

### 1) 헤더 하위 메뉴의 ARIA 오류

역할이 없는 `div`에 `aria-label`을 사용해 발생한 W3C 오류를 수정했다.

```diff
- <div class="site-header-dropdown__inner" aria-label="전체 하위 메뉴">
+ <div class="site-header-dropdown__inner" role="group" aria-label="전체 하위 메뉴">
```

재검사 결과 해당 오류가 제거되어 HTML 오류가 3건에서 2건으로 줄었다.

### 2) 모바일 메뉴의 미선언 변수와 숨김 클래스 오류

앵커 링크 처리 코드가 `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose`를 선언하지 않고 사용했다. 또한 공통 컴포넌트가 사용하는 `is-hidden`이 아니라 `hidden`을 조작하고 있었다.

```diff
+ const mobileMenu = document.getElementById('mobile-menu');
+ const menuBtn = document.getElementById('menu-btn');
+ const menuIconOpen = document.getElementById('menu-icon-open');
+ const menuIconClose = document.getElementById('menu-icon-close');

- if (!mobileMenu.classList.contains('hidden')) {
+ if (mobileMenu && menuBtn && menuIconOpen && menuIconClose &&
+     !mobileMenu.classList.contains('is-hidden')) {
    menuBtn.setAttribute('aria-expanded', 'false');
-   mobileMenu.classList.add('hidden');
-   menuIconOpen.classList.remove('hidden');
-   menuIconClose.classList.add('hidden');
+   mobileMenu.classList.add('is-hidden');
+   menuIconOpen.classList.remove('is-hidden');
+   menuIconClose.classList.add('is-hidden');
  }
```

모바일 브라우저에서 메뉴를 연 뒤 내부 앵커를 선택해 메뉴가 닫히고 `aria-expanded="false"`로 복원되는 것을 확인했다.

### 4) 이미지 로딩 우선순위와 크기 지정

히어로 이미지에는 `fetchpriority="high"`와 원본 크기 `1536×672`를 지정했다. 본문 이미지 11장에는 각 원본의 `width`와 `height`, `loading="lazy"`를 추가했다.

- 어린이·성인·시니어 이미지: `1248×832`
- TV·온라인·파트너 이미지: `1344×768`
- 히어로 이미지: `1536×672`

브라우저가 다운로드 전에 이미지 비율을 계산할 수 있어 레이아웃 이동을 줄이고, 화면 아래 이미지는 필요할 때 내려받도록 했다.

## 2 - 수정하지 않은 항목과 이유

| 항목 | 이유 |
| --- | --- |
| HTML 오류 2건(`<style type="text/tailwindcss">`, `@theme`) | Tailwind v4 브라우저 빌드가 사용하는 문법으로 제거하면 디자인 토큰이 동작하지 않는다 |
| HTML 경고 43건 | 빈 요소 끝 슬래시에 관한 권고이며 페이지 동작에는 영향이 없다 |
| Swiper CSS 및 외부 CDN JavaScript 오류 | 직접 작성한 코드가 아니므로 수정 대상에서 제외했다 |
| CDN 전역 `gsap` 등 | 실제로 페이지가 CDN에서 제공받는 전역이며 파일 단위 ESLint의 오탐이다 |
| 색 대비 문제 | 기존 검사 결과에 실패 요소 선택자가 없어 정확한 수정 대상을 확정할 수 없다 |
| 캐시 정책·렌더링 차단 리소스 | GitHub Pages 응답 정책과 외부 CDN 로딩 구조에 관련된 별도 작업이다 |
| 기존 PNG 12장 삭제 | 더 이상 참조하지 않지만 파일 삭제에는 사용자 승인이 필요해 보존했다 |

## 4 - 배포 후 다시 확인할 것

현재 변경은 로컬에만 있어 공개 URL 점수에는 반영되지 않았다. 커밋·푸시 후 GitHub Pages 배포가 완료되면 `https://icerence.github.io/kiwik-project/food4.html`을 모바일과 데스크톱에서 다시 검사해야 한다.

기존 비교 기준은 성능 모바일 56점·데스크톱 75점, LCP 모바일 32.8초·데스크톱 4.2초다. 이미지 전송량은 크게 줄었지만 새 점수와 LCP 개선 폭은 배포 후 공개 URL 측정으로 확정한다.

## 검사 도구와 한계

W3C Nu HTML Checker로 로컬 HTML을 재검사했고 Chromium 기반 자동화로 모바일·데스크톱 이미지 로딩, 메뉴 상태, 가로 넘침과 런타임 오류를 확인했다. Lighthouse 점수는 네트워크와 서버 상태에 따라 달라지므로 이 보고서에서는 새 점수를 추정하지 않았다. 접근성 자동 검사는 키보드 이동과 포커스 순서를 모두 보장하지 않는다.
