## 1 - 고친 것

### 1) 헤더 하위 메뉴의 ARIA 오류

역할이 없는 `div`에 `aria-label`을 사용해 발생한 W3C 오류를 수정했다.

```diff
- <div class="site-header-dropdown__inner" aria-label="전체 하위 메뉴">
+ <div class="site-header-dropdown__inner" role="group" aria-label="전체 하위 메뉴">
```

재검사에서 해당 오류가 사라져 HTML 오류가 3건에서 2건으로 줄었다.

### 2) 모바일 메뉴의 미선언 변수와 클래스명 오류

앵커 링크 처리 코드가 `mobileMenu`, `menuBtn`, `menuIconOpen`, `menuIconClose`를 선언하지 않고 사용했다. 실제 공통 컴포넌트의 숨김 클래스인 `is-hidden` 대신 `hidden`을 조작하는 문제도 있었다.

```diff
+ const mobileMenu = document.getElementById('mobile-menu');
+ const menuBtn = document.getElementById('menu-btn');
+ const menuIconOpen = document.getElementById('menu-icon-open');
+ const menuIconClose = document.getElementById('menu-icon-close');

- if (!mobileMenu.classList.contains('hidden')) {
+ if (mobileMenu && menuBtn && menuIconOpen && menuIconClose &&
+     !mobileMenu.classList.contains('is-hidden')) {
    menuBtn.setAttribute('aria-expanded', 'false');
-   mobileMenu.classList.add('hidden');
-   menuIconOpen.classList.remove('hidden');
-   menuIconClose.classList.add('hidden');
+   mobileMenu.classList.add('is-hidden');
+   menuIconOpen.classList.remove('is-hidden');
+   menuIconClose.classList.add('is-hidden');
  }
```

모바일 브라우저에서 메뉴를 열고 내부 앵커를 선택한 뒤 메뉴가 닫히며 `aria-expanded="false"`로 복원되는 것을 확인했다.

### 3) PNG 이미지 2장을 WebP로 전환

두 이미지를 원본 해상도로 유지하면서 WebP 품질 82로 인코딩했다.

| 이미지 | 해상도 | PNG | WebP | 감소율 |
| --- | --- | ---: | ---: | ---: |
| `food5-hero` | 1536×672 | 1,293,197바이트 | 60,808바이트 | 약 95.3% |
| `food5-pris` | 1248×832 | 1,430,680바이트 | 78,540바이트 | 약 94.5% |
| **합계** | | **2,723,877바이트** | **139,348바이트** | **약 94.9%** |

총 2,584,529바이트를 줄였다. 기존 PNG는 코드에서 더 이상 참조하지 않지만 삭제 승인을 받지 않아 보존했다.

### 4) 이미지 로딩 우선순위와 비율 정보 추가

히어로 이미지에 `fetchpriority="high"`, `width="1536"`, `height="672"`를 지정했다. PRIS 본문 이미지에는 `width="1248"`, `height="832"`, `loading="lazy"`를 적용했다.

브라우저가 이미지 다운로드 전에 원본 비율을 계산할 수 있어 레이아웃 이동과 이미지 비율 감사 개선에 도움이 된다. 히어로는 LCP 후보이므로 우선 내려받고 본문 이미지는 화면에 가까워질 때 내려받는다.

### 5) HTML 주석 문법 경고 제거

HTML 주석 안의 `--font-sans`에 연속 하이픈이 있어 XML 1.0 대응 경고가 발생했다. 설명 문구를 `font-sans`로 바꿔 연속 하이픈을 제거했다. 실제 CSS 변수 선언은 수정하지 않았다.

### 6) 제목 없는 `section` 수정

`section#sec-mission`은 `aria-labelledby="mission-heading"`을 사용했지만 연결 대상이 일반 `p`라 W3C가 제목 없는 구역으로 판단했다. 시각적 제목 역할을 하던 요소를 실제 `h2`로 변경했다.

```diff
- <p id="mission-heading">Pulmuone Food Safety &amp; Quality Policy</p>
+ <h2 id="mission-heading">Pulmuone Food Safety &amp; Quality Policy</h2>
```

스타일 클래스는 그대로 유지해 화면 디자인은 바뀌지 않는다.

## 2 - 수정하지 않은 항목과 이유

| 항목 | 이유 |
| --- | --- |
| HTML 오류 2건(`<style type="text/tailwindcss">`, `@theme`) | Tailwind v4 브라우저 빌드 전용 문법이며 제거하면 디자인 토큰이 동작하지 않는다 |
| HTML 경고 26건 | 빈 요소 끝 슬래시에 관한 권고로 페이지 동작에는 영향이 없다 |
| Swiper CSS 및 외부 CDN JavaScript 오류 | 직접 작성한 코드가 아니므로 수정 대상에서 제외했다 |
| CDN 전역 `gsap` 등 | 실제로 CDN에서 제공되는 전역이며 파일 단위 ESLint의 오탐이다 |
| 색 대비 문제 | 기존 검사 결과에 실패 요소 선택자가 없어 정확한 대상을 확정할 수 없다 |
| 캐시 정책·렌더링 차단 리소스 | GitHub Pages 응답 정책과 외부 CDN 로딩 구조에 관련된 별도 작업이다 |
| 기존 PNG 2장 삭제 | 더 이상 참조하지 않지만 파일 삭제에는 사용자 승인이 필요해 보존했다 |

## 4 - 배포 후 다시 확인할 것

현재 변경은 로컬에만 있어 공개 URL의 Lighthouse 점수에는 반영되지 않았다. 커밋·푸시 후 GitHub Pages 배포가 완료되면 `https://icerence.github.io/kiwik-project/food5.html`을 모바일과 데스크톱에서 다시 검사해야 한다.

기존 비교 기준은 성능 모바일 57점·데스크톱 73점, LCP 모바일 21.9초·데스크톱 3.5초, Best Practices 모바일·데스크톱 96점이다. 이미지 전송량은 크게 줄었지만 새 점수와 이미지 비율 감사 통과 여부는 배포 후 공개 URL 측정으로 확정한다.

## 검사 도구와 한계

W3C Nu HTML Checker로 로컬 HTML을 재검사했고 Chromium 기반 자동화로 모바일·데스크톱 이미지 로딩, 메뉴 상태, 가로 넘침과 런타임 오류를 확인했다. Lighthouse 점수는 네트워크와 서버 상태에 따라 달라지므로 이 보고서에서는 새 점수를 추정하지 않았다. 접근성 자동 검사는 키보드 이동과 포커스 순서를 모두 보장하지 않는다.
