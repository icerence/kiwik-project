## 2 - CSS 문법 (W3C CSS Validator)

오류 30건은 전부 `https://cdn.jsdelivr.net/npm/swiper@12/swiper-bundle.min.css`(외부 CDN 라이브러리)에서 나왔다. `.swiper-3d`, `.swiper-pagination` 등 최신 CSS 문법을 검사기가 오래된 규칙으로 파싱하며 생기는 오탐이며, 직접 작성한 코드가 아니므로 고칠 대상이 아니다.

경고 36건은 W3C CSS Validator API가 세부 위치를 제공하지 않아 항목 단위 확인은 안 됐다. 오류가 전부 swiper CDN 파일에서 나온 것으로 볼 때 경고도 같은 출처일 가능성이 높다. 직접 작성한 `assets/css/food-tokens.css`, `assets/css/fonts.css`, `common/components.css`에서 나온 오류는 0건이다.

## 6 - 검색 최적화와 권장 사항

검색 최적화(SEO)는 모바일·데스크톱 모두 100점으로 통과했다.

권장 사항(Best Practices)은 모바일 100점, 데스크톱 96점이다. 데스크톱에서만 걸린 항목은 위 성능 표에 함께 나온 레이아웃 이동(`layout-shifts`) 관련 감점으로, HTML 오류 4번 항목(아리아 라벨)이나 이미지 크기 미지정(`unsized-images`)과 같은 원인이다.

## 7 - 먼저 할 일

1. **히어로·본문 이미지 최적화**: `assets/images/food2-hero.png` 등 큰 이미지를 WebP/AVIF로 바꾸고 적절한 크기로 리사이즈한다. LCP가 모바일 16.5초 → 목표 4초 이하로, 성능 점수가 가장 크게 오른다.
2. **`common/components.js`의 `var` 74건을 `let`/`const`로 교체**: 동작 변화 없이 스코프 버그 위험을 없애고 최신 표준을 따른다.
3. **line 195 `<div aria-label="전체 하위 메뉴">`에 `role` 추가**: HTML 문법 오류이자 스크린리더 사용자에게 실제로 영향을 주는 항목이다.

## 검사 도구와 한계

이 보고서는 W3C Nu HTML Checker, W3C CSS Validator, ESLint(recommended), Lighthouse 결과를 옮긴 것입니다. 문법 검사는 코드가 규칙에 맞는지만 보므로, 문법이 맞아도 화면이 의도와 다르게 보일 수 있습니다. 린트는 파일 단위로 실행되어 다른 스크립트가 만드는 전역 변수를 오류로 잘못 표시할 수 있습니다(`gsap`, `mobileMenu` 등). 성능 점수는 잴 때마다 몇 점씩 달라지며, 이번 측정은 PSI API 대신 로컬 CLI로 대체됐으므로 참고용으로만 봅니다. Lighthouse 접근성 점수는 자동으로 잡히는 항목만 반영하며, 색 대비·이미지 비율 문제는 어느 요소인지 사람이 직접 확인해야 합니다.
