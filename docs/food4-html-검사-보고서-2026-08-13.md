### 경고 43건

43건은 모두 `<meta />`, `<img />`, `<br />` 등 HTML 빈 요소에 자체 종료 슬래시를 사용했다는 같은 경고다(`Trailing slash on void elements has no effect…`). HTML5에서 슬래시는 효과가 없으므로 코드 스타일을 통일하려면 제거할 수 있지만 동작 오류는 아니다.

## 2 - CSS 문법

오류 30건은 모두 외부 파일 `https://cdn.jsdelivr.net/npm/swiper@12/swiper-bundle.min.css`의 13번째 줄에서 발생한 `Parse Error`다. `.swiper-3d`, `.swiper-css-mode`, `.swiper-virtual` 등 압축된 Swiper 최신 CSS를 W3C CSS Validator가 해석하면서 발생했다. 직접 작성한 코드가 아니므로 수정 대상에서 제외한다.

경고 36건도 검사 결과에 세부 위치가 제공되지 않았다. 외부 라이브러리와 최신 CSS 기능에서 발생할 수 있으므로 출처가 확인되지 않은 상태에서 자체 코드 문제로 단정하지 않는다.

## 5 - 접근성

모바일과 데스크톱 모두 96점이다.

| 항목 | 내용 | 어떻게 고치는가 |
| --- | --- | --- |
| `color-contrast` | 일부 전경색과 배경색의 대비가 충분하지 않음 | 실패 요소를 브라우저 개발자 도구로 확인해 글자색 또는 배경색의 명도 차이를 WCAG 기준에 맞게 높인다 |

현재 스킬이 보존한 Lighthouse 요약에는 실패 요소의 선택자가 포함되지 않아 정확한 위치는 확인되지 않았다.

자동 검사로는 아래 항목을 확인할 수 없다.

1. 키보드 `Tab`만으로 화면 전체를 사용할 수 있는가
2. 포커스가 특정 영역에 갇히지 않는가
3. 시각적 순서와 DOM 순서가 일치하는가

## 6 - 검색 최적화와 권장 사항

검색 최적화는 모바일·데스크톱 모두 100점이고, 권장 사항도 모두 100점이다. 자동 검사에서 이 두 카테고리의 감점 항목은 확인되지 않았다.

성능 관련 추가 권고로 이미지 `width`·`height` 명시, 캐시 수명 개선, 렌더링 차단 요청 축소, 사용하지 않는 JavaScript 지연 로딩이 제시됐다.

## 7 - 먼저 할 일

1. 히어로와 본문 이미지를 WebP/AVIF로 최적화하고 LCP 이미지를 HTML에서 즉시 발견하도록 `preload` 또는 `fetchpriority="high"`를 검토한다. 모바일 LCP 32.8초와 전체 전송량 18,281KiB 개선에 가장 직접적이다.
2. `inline_1.js`의 모바일 메뉴 관련 변수 4개를 DOM에서 명시적으로 가져오고 실제 메뉴 숨김 클래스와 일치하는지 확인한다. 앵커 클릭 시 발생할 수 있는 `ReferenceError`를 막는다.
3. 이미지에 명시적인 `width`와 `height`를 넣고 색상 대비 실패 요소를 확인한다. 데스크톱 CLS 0.116과 접근성 감점을 함께 줄일 수 있다.

## 검사 도구와 한계

이 보고서는 W3C Nu HTML Checker, W3C CSS Validator, ESLint, Lighthouse 결과를 한국어로 옮긴 것이다. 문법 검사는 코드가 규칙에 맞는지만 보므로 문법이 맞아도 화면이 의도와 다를 수 있다. 외부 CDN 압축 코드에서 발생한 오류는 직접 수정 대상에서 제외했다. Lighthouse 점수는 네트워크와 측정 환경에 따라 달라질 수 있으며, 접근성 점수는 자동 판정 가능한 항목만 반영한다.
