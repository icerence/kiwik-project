# 보고서 틀

아래 틀에 값을 채워 마크다운 보고서를 만든다. 대괄호 안내는 실제 문장으로 갈아 끼우고 남기지 않는다.

검사하지 않았거나 실패한 항목은 표에서 지우지 말고 "확인 실패"로 적는다. 빈칸으로 두면 통과한 것으로 오해한다.

---

```markdown
# [사이트 이름 또는 주소] 검사 보고서

검사 주소: [URL]
검사 기준: 모바일 + 데스크톱 (사용자가 하나만 요청했으면 그 하나만 적는다)
검사일: [YYYY-MM-DD]

## 한눈에 보기

| HTML 문법 | 오류 [n]건, 경고 [n]건 | [통과 또는 고칠 것 있음] |
| CSS 문법 | 오류 [n]건, 경고 [n]건 | [통과 또는 고칠 것 있음] |
| JS 린트 | 오류 [n]건, 경고 [n]건 | [통과 또는 고칠 것 있음] |

| 접근성 (모바일 / 데스크톱) | [n]점 / [n]점 | [좋음 / 개선 필요 / 나쁨] |
| 검색 최적화 (모바일 / 데스크톱) | [n]점 / [n]점 | [좋음 / 개선 필요 / 나쁨] |
| 권장 사항 (모바일 / 데스크톱) | [n]점 / [n]점 | [좋음 / 개선 필요 / 나쁨] |

[가장 먼저 고칠 것 한 줄. 무엇을 고치면 어느 항목이 얼마나 나아지는지 적는다.]
```

## 채울 때 지키는 것

1. 오류가 0건이면 표를 만들지 말고 "오류 없음"이라고 한 줄로 적는다.
2. 같은 오류가 여러 줄에서 나오면 한 행으로 묶고 줄 번호를 나열한다.
3. 오류가 20건을 넘으면 상위 10건만 표에 넣고, 나머지는 "같은 유형 [n]건"으로 묶는다. 몇 건을 줄였는지 반드시 적는다.
4. "먼저 할 일"은 3개까지만 적는다. 목록이 길면 무엇부터 할지 정하지 못한다.
5. 점수만 적고 넘어가지 않는다. 그 점수가 왜 나왔는지 한 줄이라도 붙인다.
