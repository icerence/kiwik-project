# Lighthouse 결과 한국어 대응표

출처: Chrome for Developers 공식 문서. 확인일 2026-08-09.

- 성능 채점: https://developer.chrome.com/docs/lighthouse/performance/performance-scoring
- 접근성 채점: https://developer.chrome.com/docs/lighthouse/accessibility/scoring

---

## 1. 카테고리

| JSON 키 | 한국어 이름 | 무엇을 보는가 |
| --- | --- | --- |
| `performance` | 성능 | 사용자가 화면을 보기까지 얼마나 기다리는가 |
| `accessibility` | 접근성 | 누구나 화면을 읽고 조작할 수 있는가 |
| `best-practices` | 권장 사항 | 보안·콘솔 오류 등 개발 관행이 지켜졌는가 |
| `seo` | 검색 최적화 | 검색 엔진이 페이지를 이해할 수 있는가 |

점수 구간은 다음과 같다.

| 점수 | 표시 | 뜻 |
| --- | --- | --- |
| 90~100 | 좋음 | 이 항목은 더 손대지 않아도 됩니다 |
| 50~89 | 개선 필요 | 고칠 여지가 있습니다 |
| 0~49 | 나쁨 | 먼저 고쳐야 합니다 |

## 2. 성능 지표와 가중치

성능 점수는 아래 다섯 지표의 가중평균이다.

| JSON 키 | 한국어 이름 | 뜻 | 비중 |
| --- | --- | --- | --- |
| `total-blocking-time` | 총 차단 시간 | 클릭이 먹히지 않고 멈춰 있는 시간 | 30% |
| `largest-contentful-paint` | 최대 콘텐츠 표시 시간 | 가장 큰 요소가 화면에 뜨는 시각 | 25% |
| `cumulative-layout-shift` | 누적 레이아웃 이동 | 읽는 도중 화면이 밀리는 정도 | 25% |
| `first-contentful-paint` | 첫 콘텐츠 표시 시간 | 첫 글자나 그림이 뜨는 시각 | 10% |
| `speed-index` | 속도 지수 | 화면이 채워지는 빠르기 | 10% |

비중이 큰 것부터 고치면 점수가 빨리 오른다. 총 차단 시간과 최대 콘텐츠 표시 시간 둘이 절반을 넘는다.

## 3. 자주 나오는 실패 항목

| 감사 항목 `id` | 한국어 이름 | 고치는 방법 |
| --- | --- | --- |
| `uses-optimized-images` | 이미지 용량이 큽니다 | 사진을 압축하거나 WebP로 바꿉니다 |
| `unsized-images` | 이미지에 크기가 지정되지 않았습니다 | `img`에 `width`와 `height`를 넣습니다. 화면 밀림이 줄어듭니다 |
| `image-alt` | 이미지에 대체 텍스트가 없습니다 | `alt`에 그림 설명을 넣습니다 |
| `color-contrast` | 글자와 배경의 대비가 낮습니다 | 글자색이나 배경색의 밝기 차이를 키웁니다 |
| `render-blocking-resources` | 화면 표시를 막는 파일이 있습니다 | `script`에 `defer`를 붙이거나 CSS를 나눕니다 |
| `unused-css-rules` | 쓰지 않는 CSS가 있습니다 | 페이지에서 쓰지 않는 규칙을 덜어 냅니다 |
| `meta-description` | 페이지 설명이 없습니다 | `<head>`에 `<meta name="description" content="...">`을 넣습니다 |
| `document-title` | 페이지 제목이 없습니다 | `<title>`을 넣습니다 |
| `html-has-lang` | 문서 언어가 지정되지 않았습니다 | `<html lang="ko">`로 적습니다 |
| `link-name` | 링크에 읽을 이름이 없습니다 | 아이콘만 있는 링크에 글자나 `aria-label`을 넣습니다 |
| `heading-order` | 제목 단계가 건너뛰었습니다 | `h1` 다음에 `h3`가 오지 않게 순서를 맞춥니다 |
| `errors-in-console` | 콘솔에 오류가 찍혔습니다 | 브라우저 개발자 도구의 Console 탭에서 원인을 봅니다 |
| `is-on-https` | 안전하지 않은 연결입니다 | `https` 주소로 접속하게 합니다 |
| `viewport` | 모바일 화면 설정이 없습니다 | `<meta name="viewport" content="width=device-width, initial-scale=1">`을 넣습니다 |

목록에 없는 항목은 결과 JSON의 `title`과 `description`을 번역해 쓴다. 원문 `id`는 그대로 남긴다.

## 4. 접근성 점수를 읽을 때 주의할 것

접근성 점수는 axe-core 엔진의 자동 검사 결과다. 채점 방식이 다른 카테고리와 다르므로 보고서에 그대로 옮기지 않는다.

1. 항목마다 통과와 실패 둘 중 하나이며 부분 점수가 없다.
2. 배점은 항목이 사용자에게 주는 피해 정도를 따른다. 대체 텍스트 누락처럼 피해가 큰 것이 배점도 크다.
3. **자동으로 잡히는 항목만 점수에 들어간다.** 아래는 사람이 직접 확인해야 하며 점수에 반영되지 않는다.
   - 키보드 `Tab` 키만으로 화면 전체를 쓸 수 있는가
   - 포커스가 한 곳에 갇히지 않는가
   - 눈에 보이는 순서와 코드 순서가 맞는가

그러므로 접근성 100점을 "누구나 쓸 수 있다"로 옮겨 적지 않는다. "자동 검사 항목을 모두 통과했습니다"로 적고, 직접 확인할 항목을 함께 알린다.

## 5. 측정값이 흔들리는 이유

같은 페이지를 다시 재면 점수가 몇 점씩 달라진다. 인터넷 속도와 측정 시점의 서버 상태에 영향을 받기 때문이다. 판단이 필요한 자리에서는 3회 측정해 비슷하게 나오는 값을 쓴다. 한 번 잘 나온 값만 골라 적지 않는다.

모바일 기준과 데스크톱 기준은 서로 다른 조건으로 재므로 점수를 견주지 않는다. 보고서에는 어느 기준으로 쟀는지 반드시 밝힌다.
